# Security and execution-safety audit (2026-10-24)

A walk-through of every IPC command, every place a secret is handled, every path that runs SQL,
and every confirmation, as step 19 asks. Findings are fixed or recorded with a decision.
Dependency advisories are assessed separately in
[`dependency-advisories.md`](dependency-advisories.md).

## 1. Capabilities and commands

`capabilities/default.json` grants the main window `core:app:default`, `core:event:default`,
`core:window:default` and one `allow-*` permission per Quarry command. No plugin permission is
granted to the WebView: the dialog and clipboard plugins are used from Rust only, there is no
shell, fs or http plugin, and the CSP is `default-src 'self'` with `connect-src` limited to IPC.
The bindings test (`command_lists_agree`) fails if `build.rs`, the capability file, the handler
list and the UI client drift apart.

What the WebView can pass, by group, and what Rust does with it:

| Group               | Commands                                                                                              | WebView input                                                                  | Checks in Rust                                                                                                             |
| ------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| Settings, workspace | `settings_*`, `workspace_*`                                                                           | settings, opaque workspace JSON                                                | ranges validated; workspace must be an object of at most 8 MB                                                              |
| Data sources        | `connection_*`, `folder_*`, `connections_list`                                                        | drafts, ids, passwords                                                         | drafts normalized and validated; passwords are `SecretString` (never serialized back); save mode decides keyring or memory |
| SSH                 | `ssh_profile_*`, `ssh_host_trust`                                                                     | profile drafts, secrets, a fingerprint to trust                                | the fingerprint must match the key the server presented in this run                                                        |
| Files               | `file_pick`                                                                                           | a purpose                                                                      | the path comes from the native dialog                                                                                      |
| Sessions, metadata  | `sessions_list`, `metadata_*`, `object_details`, `table_model`, `ddl_generate`                        | ids, object names                                                              | catalog queries are app-authored and parameterized                                                                         |
| Running SQL         | `query_execute`, `query_cancel`, `result_refine`                                                      | SQL text, options                                                              | see section 3                                                                                                              |
| Results             | `result_page`, `result_close`, `result_format`, `result_preview_edits`, `result_apply_edits`          | cursor names, row changes                                                      | edits become parameterized statements on a side connection, all or nothing                                                 |
| Schema changes      | `schema_preview`, `schema_apply`                                                                      | a change model, or the previewed statements as edited                          | applied in one transaction on a side connection                                                                            |
| Files out           | `ddl_save`, `result_export`, `result_copy`, `history_export`, `snippets_export`, `import_errors_save` | a suggested file name                                                          | paths come only from the native save dialog; names are sanitized                                                           |
| Files in            | `import_pick`, `import_preview`, `import_run`, `snippets_import`                                      | file ids, an import plan                                                       | paths come only from the native open dialog or a drop on the window; the WebView sees an id and at most 200 preview rows   |
| Consoles            | `console_*`, `revision*`, `consoles_dir`                                                              | console names, text                                                            | names are validated so no input can leave the consoles directory; symlinks refused                                         |
| History, snippets   | `history_*`, `snippet*`                                                                               | queries, ids, drafts                                                           | FTS input is quoted as phrases; drafts validated                                                                           |
| Transactions        | `session_*`, `tx_*`, `app_quit`                                                                       | session keys, a quit resolution                                                | quitting resolves every open transaction first                                                                             |
| AI                  | `ai_*`                                                                                                | settings, the key (write-only), consent choices, preview requests, payload ids | see section 2 and ADR-0005                                                                                                 |

Findings:

- **A1 (accepted)**: TLS certificate and key paths and the SSH key path are fields of the data
  source draft, so the WebView supplies them (after the user picked them in the native dialog or
  typed them). Rust reads those files at connect time, parses them as PEM, and never returns
  their content; errors name the path only. A compromised WebView could point them at another
  file, but would learn nothing beyond "not a PEM file". Decision: accept; the alternative
  (dialog-issued ids) would make profiles impossible to edit by hand.
- **A2 (by design)**: `schema_apply` runs statements the user may have edited in the preview
  (step 06). They run in one transaction on a connection that inherits the profile's read-only
  setting.

## 2. Secrets

| Secret                         | Where it lives                                                               | Never in                                            |
| ------------------------------ | ---------------------------------------------------------------------------- | --------------------------------------------------- |
| Database password              | keyring (`forever`), process memory (`until restart`), or not kept (`never`) | app.db, logs, IPC responses                         |
| SSH password or key passphrase | keyring account `ssh:<id>:password` or `ssh:<id>:passphrase`, or memory      | same                                                |
| Anthropic API key              | keyring account `ai:anthropic:api-key`, set write-only                       | same, plus AI request bodies and the AI request log |

- `SecretString` zeroizes on drop, prints as `SecretString(***)`, and has no `Serialize`, so it
  cannot be returned over IPC by accident.
- The redacting logger masks URL credentials, `password=`/`token=`/`api_key=`-style fields, JSON
  secret fields and `sk-ant-` keys in every event before it is written.
- Canary tests (each plants a marker secret and scans the outputs):
  - `crates/connections/src/tests.rs` (`secrets_never_reach_app_db_or_serialized_profiles`)
  - `crates/connections/tests/log_canary.rs` (database and SSH secrets, log file at trace)
  - `crates/ai-anthropic/tests/log_canary.rs` (API key, log file at trace with the HTTP stack)
  - `apps/desktop/src-tauri/src/ai/mod.rs` (`the_key_stays_out_of_app_db_and_ipc_responses`)
  - `apps/desktop/src-tauri/src/ai/requests.rs` (`the_log_holds_exactly_what_was_sent_and_never_the_key`)
  - `apps/desktop/src/features/settings/ai.test.tsx` (the key is not in the page after saving)
- Keyring save modes and rollbacks are covered in `crates/connections/src/tests.rs` (a keyring
  failure rolls back the create; changing the save mode moves the secret; delete removes it).

No findings.

## 3. Running SQL

Every path that runs SQL, and what guards it:

| Path                                          | Guard                                                                                                                                                                                                                                                                                   |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Run in a console (`query_execute`)            | UI: statement classifier; read-only blocks writes before sending; destructive statements and any write on production ask first. Server: read-only profiles connect with `default_transaction_read_only=on`, and switching a read-only session to read-write is rolled back and refused. |
| Sort and filter of a result (`result_refine`) | wraps the original query; values bound as parameters                                                                                                                                                                                                                                    |
| Data edits (`result_apply_edits`)             | preview of the exact statements; production asks first; parameterized; one transaction on a side connection; read-only profiles refuse at the server                                                                                                                                    |
| Schema changes (`schema_apply`)               | preview of the exact statements; destructive or production asks first; one transaction                                                                                                                                                                                                  |
| Import (`import_run`)                         | production asks first; read-only refused; one transaction, nothing left behind on failure                                                                                                                                                                                               |
| AI output                                     | never run: it is inserted as editor text and goes through Run like anything typed                                                                                                                                                                                                       |
| Metadata, DDL, sample rows for AI             | app-authored, parameterized or quoted identifiers                                                                                                                                                                                                                                       |

- Classifier coverage (`lib/sql/classify.test.ts`): reads, writes, DDL, session statements,
  data-modifying CTEs, `SELECT INTO`, `EXPLAIN ANALYZE` (counts as running its statement),
  unknown statements (treated as writes), and destructive reasons (DROP, TRUNCATE, ALTER … DROP,
  DELETE or UPDATE without WHERE).
- Confirmation paths and their tests: run (`features/exec/runQuery.test.tsx`), transactions
  (`transactions.test.tsx`), data edits (`results/editing.test.tsx`), schema changes
  (`schema/schemaTools.test.tsx`), import (`import/importWizard.test.tsx`), AI-inserted SQL
  (`ai/assistant.test.tsx`: a destructive statement still asks; a write on a read-only source is
  still blocked).
- **S1 (by design)**: the destructive and production confirmations live in the UI. They are aids
  against mistakes, not permissions; the permission (read-only) is enforced by the server for
  every connection a read-only profile opens.

## 4. Faults

`crates/db-postgres/tests/fault_pg.rs` puts a TCP proxy between the adapter and the server and
checks that every scenario ends in a state the UI can act on, within a time limit:

| Scenario                     | Outcome                                                                                                                           |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Network drops mid-query      | the call fails as connection lost, the session is closed, a new connection works                                                  |
| Drop between result pages    | the next page fails as connection lost                                                                                            |
| Drop during an export        | connection lost; no file, no partial file left                                                                                    |
| Server restart               | the open session is lost; connecting is refused (kind `refused`) until it is back, then works                                     |
| Silent network               | connect fails at the connect timeout (kind `timeout`); a running call returns as soon as Stop's second stage drops the connection |
| Permission denied mid-script | an ordinary error (SQLSTATE 42501); the session stays usable                                                                      |
| SSH tunnel drops             | the session is marked lost (`ssh_pg.rs`)                                                                                          |

## 5. `freezePrototype`

Revisited with Monaco 0.57.0 (the newest release): `vs/base/common/keyCodes.js` still assigns
`toString` on ordinary objects (`KeyCodeUtils.toString = toString`), which throws once
`Object.prototype` is frozen. The decision in `dependency-advisories.md` stands
(`freezePrototype: false`, with the CSP, the capability allow-list and Rust-side validation as
the protections).
